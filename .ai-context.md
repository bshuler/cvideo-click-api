# AI Context and Guidance for cvideo-click-api Repository

This file provides comprehensive guidance for AI assistants working on this repository. Read this file first before making any changes to understand the project's architecture, patterns, and constraints.

## Project Overview

**Repository Purpose**: AWS Lambda-based API for the cvideo-click project using Infrastructure as Code (IaC) principles and serverless architecture.

**Core Technologies**:

- **Terraform**: Infrastructure management for Lambda functions, API Gateway, and supporting services
- **Python + boto3**: All Lambda functions, automation scripts, and AWS interactions
- **Make**: Workflow orchestration and task automation
- **GitHub Actions**: CI/CD pipeline with intelligent local/production detection
- **AWS Lambda**: Serverless compute for API endpoints
- **API Gateway**: REST API management and routing

**No Bash/Shell Scripts**: All automation must use Python and boto3. Bash scripts are deprecated.

## Code Quality Standards

### **Python Development Standards**

- **Formatter**: Black with 88-character line length

### **Handler Function Pattern**

```python
import json
import logging
from typing import Dict, Any
from shared.utils import setup_logging

logger = setup_logging(__name__)

def lambda_handler(event: Dict[str, Any], context: Any) -> Dict[str, Any]:
    """
    Lambda handler function.
    
    Args:
        event: Lambda event data
        context: Lambda context object
        
    Returns:
        API Gateway response format
    """
    try:
        logger.info(f"Processing request: {event.get('httpMethod')} {event.get('path')}")
        
        # Process request
        result = process_request(event)
        
        return {
            'statusCode': 200,
            'headers': {
                'Content-Type': 'application/json',
                'Access-Control-Allow-Origin': '*'
            },
            'body': json.dumps(result)
        }
    except Exception as e:
        logger.error(f"Error processing request: {str(e)}")
        return {
            'statusCode': 500,
            'headers': {
                'Content-Type': 'application/json',
                'Access-Control-Allow-Origin': '*'
            },
            'body': json.dumps({'error': 'Internal server error'})
        }
```

### **VS Code Extension Limitations**

**Key Insight**: VS Code extensions can have validation gaps and shouldn't be the sole source of code quality validation.

**Common Issues**:

- GitHub Actions extension may show false positives for environment variables
- Lambda/serverless extensions may not recognize all AWS context patterns
- API Gateway OpenAPI validation may be incomplete

**Solution Strategy**:

- Implement comprehensive external validation tools
- Document proper usage patterns with code comments
- Use industry-standard linting tools rather than relying solely on IDE extensions
- Maintain validation automation in CI/CD pipelines
